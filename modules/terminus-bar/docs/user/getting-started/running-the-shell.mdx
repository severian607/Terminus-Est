:::tip[Method]
Use compositor autostart as the primary method.
:::
### Autostart by your Wayland compositor
This is the recommended method for launching terminusbar, as it integrates with your window manager.

For the *Niri* compositor, add the following line to the end of your configuration file, typically located at `~/.config/niri/config.kdl`
```ini
spawn-at-startup "terminusbar"
```

For the *Hyprland* compositor, append this to your existing `hyprland.start` event hook in your Lua configuration file, typically located at `~/.config/hypr/hyprland.lua`
```lua
hl.on("hyprland.start", function()
  hl.exec_cmd("terminusbar")
end)
```

If your compositor expects startup commands to return after the shell has initialized, run TerminusBar in daemon mode:
```bash
terminusbar --daemon
```
Daemon mode returns after the shell has initialized. The optional polkit authentication agent starts asynchronously after the UI is up.

---

### Manual Launch for Debugging
The most direct way to run TerminusBar for testing or debugging. Open a terminal and execute:
```bash
terminusbar
```

### Logs
TerminusBar writes its main log to `$XDG_CACHE_HOME/terminusbar/terminusbar.log`. If
`XDG_CACHE_HOME` is unset, the fallback path is
`~/.cache/terminusbar/terminusbar.log`. The previous file is retained as
`terminusbar.log.1` when the current log reaches 1 MiB.
